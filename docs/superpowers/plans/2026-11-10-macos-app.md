# GlobeRater pour macOS — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** une app macOS native (fenêtre, Réglages, barre de menus, 5 widgets) qui reprend les fonctions de GlobeRater Android avec le style macOS.

**Architecture :** un package Swift `GlobeKit` (logique pure, testée avec `swift test`), un dossier `WidgetUI` (vues des widgets et AppIntents, compilé dans l'app et dans l'extension), une cible app et une cible extension WidgetKit, générées par XcodeGen. App et extension partagent un App Group (UserDefaults + fichier JSON).

**Tech Stack :** Swift 6.1, SwiftUI, WidgetKit, AppIntents, CoreLocation, ServiceManagement, Swift Testing, XcodeGen, Xcode 16.4. Aucune dépendance externe.

**Spec :** `docs/superpowers/specs/2026-11-10-macos-app-design.md`

## Global Constraints

- Système minimum : macOS 14.0 (`MACOSX_DEPLOYMENT_TARGET = 14.0`, `platforms: [.macOS(.v14)]`).
- Bundle IDs : `ch.tageoa.globerater` (app), `ch.tageoa.globerater.widgets` (extension). Version `1.0.0`, build `1`.
- App Group : `$(TeamIdentifierPrefix)ch.tageoa.globerater` dans les entitlements ; le code lit l'identifiant résolu dans la clé Info.plist `GRAppGroup`.
- Signature automatique, Personal Team. `DEVELOPMENT_TEAM` vient de `macos/Config/Signing.xcconfig`, ignoré par git (modèle `Signing.xcconfig.example`).
- Aucune dépendance externe, aucun analytics. Réseau : seulement `openexchangerates.org` et `open-meteo.com`.
- Tout texte visible passe par `String(localized:)` / `LocalizedStringKey` avec une clé de `Localizable.xcstrings`. Aucun texte en dur dans les vues.
- Valeurs par défaut (identiques à Android `AppSettings.kt`) : entrées `USD, EUR, GBP` ; sorties `USD, EUR, GBP, JPY, CAD` ; budget `2000 USD`, période `monthly`, période affichée `monthly`, heure de remise `0`, intervalle des taux `1` jour, °C.
- Météo périmée après 3 h ; taux périmés après l'intervalle choisi.
- Commits : messages en anglais, **sans** ligne `Co-Authored-By` Claude.
- Le budget suit Android : la remise à zéro suit la **période affichée** ; la limite affichée vaut `montant × jours(période affichée) / jours(période du budget)` avec jours = 1, 7, 30, 365.

## Review Focus

1. **Séparateur décimal au clavier** : en français, l'utilisateur tape `12,5` ou `12.5` dans le champ de l'app ou du panneau ; les deux doivent donner 12,5. → test dans la tâche 2.
2. **Écritures concurrentes** : l'extension (touche « + ») et l'app ajoutent une dépense à quelques ms d'écart ; aucune ne doit être perdue. → test dans la tâche 4 (deux instances `BudgetLedger` sur le même fichier).
3. **Taux inconnu pour la devise d'une dépense** : la dépense est comptée telle quelle, sans être perdue (comportement Android). → test dans la tâche 4.
4. **Changement de devise du budget après des dépenses** : les dépenses gardent leur devise d'origine et sont converties à la lecture ; le total reste juste. → test dans la tâche 4.
5. **Changement d'heure** : une remise quotidienne à 2 h le jour du passage à l'heure d'été (Europe/Zurich, 29 mars 2026) ne doit ni sauter de période ni tomber dans le futur. → test dans la tâche 3.

### Task 3 : périodes de budget

**Files :**

**Interfaces :**
- Produces :
  - `public enum BudgetSpan: String, Codable, CaseIterable, Sendable { case daily, weekly, monthly, yearly; var days: Int }` (1, 7, 30, 365)
  - `public struct BudgetSettings: Codable, Equatable, Sendable { var enabled = true; var amount = 2000.0; var currency = "USD"; var span = BudgetSpan.monthly; var displaySpan = BudgetSpan.monthly; var anchor: Date; var refreshHour = 0; var displayLimit: Double }` — `displayLimit = amount * Double(displaySpan.days) / Double(span.days)`.
  - `public enum BudgetPeriod { static func start(index: Int, anchor: Date, refreshHour: Int, span: BudgetSpan, calendar: Calendar) -> Date; static func currentStart(anchor:refreshHour:span:now:calendar:) -> Date; static func nextStart(anchor:refreshHour:span:now:calendar:) -> Date }` — `calendar` par défaut `.current`.

Algorithme (port de `BudgetRefreshCalculator.kt`) : `start(index:)` = jour de `anchor` à `refreshHour:00:00`, puis `calendar.date(byAdding: unité, value: index)` (`.day`, `.weekOfYear`, `.month`, `.year`) ; si l'heure n'existe pas ce jour-là (changement d'heure), utiliser `calendar.date(bySettingHour:minute:second:of:matchingPolicy: .nextTime)`. `currentStart` estime `n = floor((now - start(0)) / (days × 86 400 s))`, puis corrige : décrémenter tant que `start(n) > now`, incrémenter tant que `start(n+1) <= now`.
